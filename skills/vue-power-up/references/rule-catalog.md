# Rule Catalog

The single source of truth for vue-power-up rules. The write workflow and the review command both use these rules.

## Rule ids

`VUE-<DOMAIN>-<NNN>`, for example `VUE-PINIA-001`.

- Ids are **stable**. A rule is never renumbered, and a retired rule's id is never reused. Mark it *Retired* in the index instead.
- `NNN` is three digits, assigned in order within the domain.

| Domain | Covers |
|---|---|
| `TS` | TypeScript in SFCs: typing props, emits, slots, refs, provide/inject; strictness |
| `REACT` | Reactivity: `ref`/`reactive`, `computed`, watchers, destructuring |
| `COMP` | Component design: props, emits, `defineModel`, slots, composition, naming |
| `TPL` | Templates: directives, keys, template logic, accessibility basics |
| `CMPS` | Composables: naming, inputs, return shape, cleanup, side effects |
| `PINIA` | Pinia stores: definition, consumption, SSR |
| `NUXT` | Nuxt: data fetching, SSR state, server routes, config, middleware, plugins |
| `SEC` | Security: XSS, URLs and redirects, secrets, server input, cookies, SSRF |
| `PERF` | Performance: reactivity cost, rendering, lazy loading, large lists |
| `TEST` | Testing: tools, structure, async, isolation |

## Severities

| Severity | Meaning | Write mode | Review verdict |
|---|---|---|---|
| `error` | A bug, data leak or security issue: wrong behaviour now or under realistic input | Never produce it. Deviating requires the user to insist (see SKILL.md) | Any `error` → **Request changes** |
| `warn` | Fragile, legacy or unidiomatic: works today, but breaks easily or costs maintainers | Avoid. Only use it with a stated reason | Contributes to **Approve with suggestions** |
| `info` | Style or opinion, including community conventions without official backing | Follow the project's existing convention instead | Mention briefly; never blocks |

A rule that isn't backed by official documentation (Vue, Nuxt, Pinia, TypeScript, eslint-plugin-vue, OWASP) can't be stricter than `info`.

## Rule template

Every rule in a `references/*.md` file uses exactly this shape:

````markdown
### VUE-<DOMAIN>-NNN · <Imperative title>  `<severity>`

**Why:** <one or two sentences: the concrete failure this prevents>
**Source:** <official documentation URL>

```ts
// ❌ <what goes wrong>
<minimal bad example>

// ✅
<minimal good example>
```

**Applies:** <package and version range, e.g. "Vue ≥ 3.4"> · **Exceptions:** <when the rule doesn't apply, or "none">
````

**Template conventions:**
- **Examples** are minimal and valid TypeScript for the stated versions. Use `vue` fences when the template matters.
- **Applies** gives the versions where the *recommended* fix exists. Below that range, don't flag the pattern, and in write mode use the best alternative the version allows.
- **Exceptions** list the legitimate uses, so reviews don't produce false positives.
